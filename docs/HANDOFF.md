# AP Food + FIF · Engineering overview

AP Food is a campus food pickup app for students, stall vendors and cafeteria administrators. FIF (Food Intelligence Framework) suggests each role's next action. The product scope is in [MVP.md](MVP.md); setup, endpoints and backend rules are in [BACKEND.md](BACKEND.md).

## Run and verify

1. `npm ci`, fill in `.env.local` (see [BACKEND.md](BACKEND.md)), then `npm run dev` and open http://localhost:3000.
2. Sign in with accounts provisioned in the connected project. `supabase/fixtures/demo-accounts.json` describes a fresh demo setup; an existing hosted project may still use older local fixture credentials. The misleading quick-fill list has been removed. Use separate browser profiles for several roles. Do not reset an existing demo project just to align credentials.
3. Before handing changes back, run `npm run format`, `npm run typecheck`, `npm run build`, `npm test` and `npm run test:backend`.

The hosted demonstration now includes a busy November dataset across all ten stalls: 15,586 additional orders through 12 November, with matching receipts and expenses. The 2024 and 2025 demonstration activity has been removed; 2023 and 2026 remain. See [CAMPUS_MONTH_DATA.md](CAMPUS_MONTH_DATA.md) for verified counts, private backup locations and repeatable setup. Reports load complete paginated data; the vendor dashboard includes a default 30-day revenue outlook and an optional FIF scenario. Generated fixture passwords remain in ignored local files.

## Features

The admin command centre now includes cross-vendor oversight, 90-day aggregate reporting, vendor review drawers, Gemini-written recommendations, a read-only management assistant and a consistent warm operations theme. See [ADMIN_COMMAND_CENTRE.md](ADMIN_COMMAND_CENTRE.md) for APIs, financial definitions, applied migrations and verification.

The [order fulfilment check](ORDER_FULFILMENT_CHECK.md) records the hosted cancellation repair, eight-digit pickup-code rollout and My Orders Active/History split, including verification and current history limits.

The current functionality review and its remaining verification limits are in [FUNCTIONALITY_AUDIT.md](FUNCTIONALITY_AUDIT.md). Vendor FIF automatically checks sales, peak periods, stock, the live kitchen queue, published campus prices, campus timing and local weather when generating insights. Its evidence drawer distinguishes missing observations from assumptions. Revenue/workload charts are what-if estimates, not measured uplift.

## Checks to keep passing

- Student checkout → vendor ready → student pickup code → vendor collection → exactly one receipt.
- Concurrent checkouts cannot exceed stall capacity or stock; retries with the same key create one order.
- Promotions agree in the storefront, cart, order snapshot and receipt.
- An expense reduces net flow and its reversal restores it, keeping both entries.
- Students and stalls only see their own orders.
- The three workspaces stay usable at 390, 768 and 1440 px wide.
